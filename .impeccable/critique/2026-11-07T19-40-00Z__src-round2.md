## Two claims checked before acting, and the result

**The light-theme hero failure is real; the stated mechanism was wrong.**
Measured in the running app, light theme: "Minecraft 1.21.1" at **2.90:1**, the
loader pill at **3.21:1**, the play-time line at **4.42:1**. The report
attributed this to `.heroScrim` applying only when an instance has banner art.
It does not — `InstanceView.tsx` renders it unconditionally in both branches.
The actual cause is the generated wash, `hsl(<hue> 44% 30%)` → `hsl(<hue+55>
42% 18%)`, whose lightness is hardcoded dark in **both** themes while the text
over it flips dark in the light one; the scrim then fades toward a near-white
`--surface` and lifts the bottom of a dark field into exactly the mid-grey band
the stats line occupies. The proposed fix would not have fixed the defect.

**The ignore-version control is not colour-only, as claimed.** `ContentTab.tsx`
renders an "any version" text badge for that state and the toggle carries
`aria-pressed`; `.anyVersion` tinting it `var(--warn)` is a redundant second
channel. No change was made on this finding.

## The gap in the contrast test this round exposed

`src/lib/contrast.test.mjs`, added in round one, measures every text token
against every surface token in both themes — and could not see the hero at all,
because the hero's background is not a token. It is a runtime gradient built in
TSX from `hashHue(instance.id)`, so the failing surface never appears in
`global.css` for the test to read. A token-to-token test cannot catch a
generated background; the fix has to sweep the hue range.

## Rig limits, unchanged from round one and still load-bearing

Tauri on Linux uses WebKitGTK, which exposes no CDP, so the detector's browser
half cannot attach to the real app window; it degrades to a source scan plus a
URL scan of the vite dev server, which has no Rust backend and therefore renders
only the Library route and four "could not load" toasts. Those toasts and the
empty routes are the rig, not defects. Separately, a ratio measured on a hidden
background page is suspect: CSS transitions freeze at their start value with no
`requestAnimationFrame`, and three light-theme ratios in this round (1.61, 2.48,
1.03) were artifacts of exactly that and were withdrawn after re-measurement.

One finding generalised rather than fixed as reported: a single 10.5px sidebar
shortcut hint was the one instance of its class the detector could reach. The
class was 14 sub-11px declarations across 12 module CSS files; all were raised
to an 11px floor in `e0ded45`.

## Design Specificity Verdict

**The thinking is unmistakably Geode's; the skin is a template.**

For: the New server dialog groups 14 kinds by what the choice does for you and spends a whole group — "Not a server" — on preventing one specific newcomer mistake. Three distinct Browse surfaces, each correctly different in tab set, verb and filter semantics. Java runtimes labelled by the Minecraft versions they serve. "This machine has 31.2 GB. Giving Minecraft more than about half of it usually makes stutter worse, not better."

Against: strip the words and the shell is the 2023 dark-SaaS default — 200px rail, uppercase grey captions, one 13px system sans with weight as the only hierarchy device, Lucide icons as shipped. Nothing in the chrome is Minecraft. The generated accent-blur banner is identical for every instance, so the most-seen screen has no identity.

**Deterministic scan.** Source: `detect --json src/` over 109 files, exit 0, zero findings — but regex-only, so parsed-page rules never ran; an undercount, not a clean bill. URL scans at 1280x800 and 940x620: 14 findings each, byte-identical. 9 primary were all one token, `--text-faint` on dark surfaces (2.9–4.0:1). 1 script-error and 4 straggler advisories were no-backend artifacts and are false positives. Four `design-system-*` rules could not run: there is no DESIGN.md, so "no drift" means "no rule input".

**Visual overlays.** None. Tauri on Linux (WebKitGTK) exposes no CDP, so the overlay could not attach to the real window; the detector reached the vite-served frontend instead, which has no backend and renders only the Library shell. Browse — the screen most of today's layout work touched — was never scanned.

## Overall Impression

A product whose specificity lives almost entirely in language and information architecture, and almost not at all in form. The writing and the IA are genuinely ahead of the category; the surface is interchangeable. The single biggest opportunity is that the product's best idea — grouping choices by what they do for you — appears exactly once, in the New server dialog, while the two screens that most need it (the mod-loader row, the re-target candidate list) do the opposite.

## What's Working

**The New server dialog's grouping.** Group headings are the user's question rather than the vendor's taxonomy, and it teaches server hosting in the act of asking you to choose.

**Three Browse surfaces that know who they're feeding.** Scope chip, correct verb, correct tab set, and filter semantics that change with scope and say so.

**Helper copy that gives you the number, not the warning.** A fact about your machine and a consequence in your terms, then stops.

## Priority Issues

**[P1] The re-target dialog's primary button names the wrong operation under its own default.** "Apply to" defaults to "A copy if there is anything to lose"; the footer always reads "Move to Minecraft 26.3" and never changes. The one action the dialog calls irreversible is labelled with the wrong verb. Fix: drive the label from the mode, and move the mode above the candidate list. → /impeccable clarify

**[P1] Every disabled text input, select and textarea looks enabled.** `global.css` has no `:disabled` rule for fields; all 13 existing ones target buttons. The Accounts offline-username field accepts clicks and types nothing. Fix: one rule beside `.btn:disabled`. → /impeccable harden

**[P1] Six interchangeable rows where the product's promise is that it decides for you.** The re-target list and the plan rail both render 6+ candidates reading the same sentence, with no discriminating information and no date — while New instance prints a release date beside every version. Fix: lead with the answer, collapse the rest, put dates on every row. → /impeccable distill

**[P2] Four different save models across screens all called "Settings".** Sticky save bar, instant apply, save-on-blur stated once, and explicit Save buttons. A user learns one rule and it is wrong three screens later. → /impeccable harden

**[P2] The Worlds tab shows a version mismatch as if it were a genre tag.** The app holds both numbers and declines to compare them, in the one place where there is no upstream to re-fetch from. → /impeccable clarify

## Persona Red Flags

**Alex (power user).** Five global bindings, all navigation. No Ctrl+S when the save bar says "You have unsaved changes", no Ctrl+N, no Delete on a focused row. Enter-to-submit is bound in five dialogs but not in New instance or New server. No bulk selection anywhere: 40 mods means 20 clicks to disable half.

**Riley (stress tester).** Types into the disabled offline-username field and concludes the app froze. Finds Fabric API at 284M/"Modrinth" on one Browse and 526M/"Modrinth + CurseForge" on another — deterministic, not a race, and presented as plain fact either way. Opens Install… on an already-installed mod and finds the button still enabled with nothing saying what a second install does.

**Jordan (first-timer).** Two identical accent-filled buttons for the one available action on first run. Meets "Mod loader: Vanilla | Fabric | Quilt | NeoForge | Forge" with no explanation — in an app that explains what a plan is, what a proxy is, and what Java 17 is for. Reaches a panel headed "SIGNED IN" that says "No accounts yet."

## Minor Observations

"MR" survives in PlanView where the codebase decided it shouldn't, and `providerShort()` is dead code. The Dependencies tab leaves its whole toolbar live over an empty canvas. "Import folder" means two different things with the same icon. The About update error pastes a request URL at a player. The custom accent swatch is indistinguishable from a preset. The Share menu's second group has no heading. At 940x620 everything reflows cleanly except the New server dialog, which hides the version field, the name field and the EULA sentence below an unindicated fold while "Create server" stays pinned and enabled.

## Questions to Consider

1. If the resolver can tell you which version is best, why present six?
2. The product's best idea — grouping by what a choice does — appears once. What would the mod-loader row look like with the same treatment?
3. The writing is doing all the differentiating work. Is that a decision, or where the energy happened to go?
4. Settings admits the app cannot verify the sharing configuration it just asked for. Is the absent "Test this address" technical or just unbuilt?
5. Every list is one-at-a-time. Was no-bulk-selection a position or an omission?
